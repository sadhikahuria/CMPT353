1. Timing results (all run with --master="local[1]" on CSIL)

   1. reddit-0, schema supplied, cache on: real 0m7.855s
   2. reddit-2b, no schema, no cache: real 0m13.341s
   3. reddit-2b, schema supplied, no cache: real 0m8.896s
   4. reddit-2b, schema supplied, cache on: real 0m7.884s

   These were all run back to back on the same CSIL machine, so they should be comparable to each other. The exact seconds would probably shift a bit on a different machine or a busier day, since Spark timing is never perfectly consistent, but the pattern between them should hold.

2. (2) - (3) = 13.341 - 8.896 = 4.445s saved by adding the schema
   (3) - (4) = 8.896 - 7.884 = 1.012s saved by adding the cache

   Schema saved around 4x more time than caching did. So it looks like most of the avoidable time on reddit-2b was going into Spark reading the file and inferring the schema itself, not the repeated calculation of the averages. That matches what run (4) being barely above the reddit-0 baseline (7.884s vs 7.855s) already suggests: almost all of the reddit-2b time is just fixed Spark startup cost either way, and schema inference is probably the biggest real chunk of work actually being wasted in (2).

3. I used .cache() once in wikipedia_popular.py, right after filtering the data down to English, non-Main_Page, non-Special pages. Thatfiltered DataFrame gets used twice after that point - once to find the max views per hour, and again in the join that pulls out every row matching that max - so caching it there means Spark only reads and filters the input once instead of twice.
